# 文档评分并行处理

## 目的

RAG 检索默认返回 8 个候选文档（`AGENT_TOP_K=4` 时按 `top_k * 2` 召回）。每篇文档都需调用一次相关度评分模型；串行调用会累计等待时间。

## 实现

`agent/rag.py` 的 `grade_documents()` 使用 `ThreadPoolExecutor` 并行执行评分：

- 默认最多 4 路并发；8 篇文档通常分两批完成。
- 评分结果按候选文档原顺序返回，保证后续 `zip(candidates, grades)` 对应正确。
- 提交任务时复制 `contextvars`，使 LangSmith 将并行评分关联到同一条 LangGraph 运行。

## 配置

```env
AGENT_LLM_GRADER_MAX_CONCURRENCY=4
```

- 设为 `1`：恢复串行，便于排查问题。
- 建议保持 `4`：兼顾时延与接口并发压力。
- 上限由配置校验限制为 `8`。

## LangSmith 表现

每篇文档评分仍是一条独立的模型调用记录；并行只改变开始时间和总耗时，不会将 8 次调用合并为 1 次。复制 tracing context 后，这些记录会作为 `grade_docs` 的子运行显示。

## 注意事项

评分模型调用失败时，单篇文档仍会回退到启发式评分，不会中断整轮 RAG。
