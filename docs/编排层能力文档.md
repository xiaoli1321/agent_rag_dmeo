# 智能客服 AI 编排层 (LangGraph) 业务与技术说明书

> **模块名称**: 编排层 (LangGraph Orchestration Layer)  
> **适用对象**: 产品经理 (PM)、架构师、客服主管、交付与开发团队  
> **核心工具**: `langgraph.graph.StateGraph` + `langgraph.checkpoint.memory.InMemorySaver`

---

## 1. 编排层核心设计与状态机图解

编排层是客服 Agent 的“中枢调度引擎”，负责连接感知层、知识库 (RAG)、情绪安抚、槽位追问及人工坐席交接。

系统通过 `StateGraph` 构建离散状态机，**强制以【感知节点】作为图的唯一入口 (START)**，保障所有请求经过统一的语义与情绪理解后再进行条件分流。

### 1.1 状态机架构流程图

```
                  ┌────────────────────────┐
                  │      START (用户消息)   │
                  └───────────┬────────────┘
                              │
                              ▼
                 ┌───────────────────────────┐
                 │  感知节点 (intent_perception)│  <── 唯一入口
                 └────────────┬──────────────┘
                              │

      │ 😡 负面/愤怒/抱怨    │   │ 📘/🛠️ 产品/使用问题│   │ 🎧 售后诉求/要求人工  │
```

## 2. 核心条件路由机制 (Conditional Routing)

编排层根据感知层输出的结构化结果，按**固定业务优先级**执行条件分支路由：

| 条件判定依据 | 目标处理节点 | 业务行为说明 |
| :--- | :--- | :--- |
| **情绪为 `愤怒` 或 `不满`** | `empathy_agent` (安抚节点) | 优先生成同理心安抚话术，降低用户冲动；若判定为**安抚无效**（如连续2轮负面情绪）或包含退款诉求，节点内部通过 `Command(goto="after_sales")` 提权升级转人工。 |
| **意图为 `产品咨询` / `使用问题`** | `product_consultant` (产品节点) | 触发 RAG 检索子图（混合检索 + 重排序 + 拒答判断）。若连续 2 轮检索不到知识依据，产品节点主动提权转交人工。 |
| **显式 `转人工` 或 `售后诉求`** | `after_sales` (售后节点) | 跳过机器人回答，生成包含历史对话、意图情绪、知识命中的**结构化交接工单**直通客服坐席。 |
| **关键信息缺失 (需追问)** | `clarify` (澄清节点) | 每轮对话只追问 1 个关键缺口，并吐出前端一键点击快捷按钮。 |
| **无意义问候或域外表达** | `smalltalk` (闲聊节点) | 给出礼貌引导，不打扰客服坐席与知识库。 |

## 3. 状态 Schema (`AgentState`) 字段设计理由说明

`AgentState` 是贯穿整个 LangGraph 图生命周期的全局共享状态，**每个字段均有明确的业务与技术存在理由**：

| 字段名称 | 类型 | 存在理由 (Business & Technical Rationale) |
| :--- | :--- | :--- |
| **`messages`** | `list[BaseMessage]` | **【对话上下文】** 基于 LangChain `add_messages` 增量追加底层消息流，为模型与坐席提供多轮对话依据。 |
| **`perception`** | `PerceptionResult` | **【全局感知结论】** 存放当前轮感知层输出（意图、情绪、置信度、实体），供下游所有节点统一消费决策。 |
| **`intent_draft`** | `IntentDraft` | **【原始语义结构】** 模型直接产出的 Pydantic 语义结构，实现大模型推断与后续确定性业务规则引擎的解耦。 |
| **`active_agent`** | `ActiveAgent` | **【当前激活节点】** 标记当前负责处理的节点标识（如 `product_consultant` / `after_sales`），驱动图路由流动。 |
| **`empathy_prefix`** | `str \| None` | **【安抚前缀】** 存储安抚节点生成的共情话术前缀。由后续专业 agent 拼接在回答开头，避免重复调用大模型生成安抚。 |
| **`current_topic`** | `str \| None` | **【跨轮主题锁定】** 记录会话锁定的标准产品型号（如 `GS3`）。**支持指代继承**（如用户第二轮问“它防水吗”时自动识别“它”= `current_topic`）。 |
| **`current_issue`** | `str \| None` | **【跨轮故障锁定】** 记录会话锁定的具体现象（如 `蓝牙连不上`），保证追问和多轮交流时不丢故障上下文。 |
| **`retrieved_docs`** | `list[RetrievedDoc]` | **【RAG 命中文档】** 记录知识库检索到的片段，用于生成回答、事实归因审计以及转人工时给坐席参考。 |
| **`dialogue_status`** | `DialogueStatus` | **【对话生命周期】** 标记对话状态（`ready` 就绪 / `awaiting_clarification` 待补充 / `handed_off` 已转人工 / `completed` 完成）。 |
| **`pending_clarification`** | `PendingClarification` | **【追问状态记录】** 记录追问轮数、已问槽位与缺失槽位，配合业务防死循环（超过 2 轮自动转人工）。 |
| **`consecutive_angry_count`** | `int` | **【安抚无效计数】** 记录连续出现负面/愤怒情绪的轮数。当超过设定阀值（如 2 轮）时判定安抚无效，无缝转人工。 |
| **`failed_rag_count`** | `int` | **【RAG 失败计数】** 记录连续 RAG 知识检索失败的次数。连续 2 轮找不到依据自动转人工，防止机器人瞎编。 |
| **`handoff_reason`** | `str \| None` | **【转人工原因】** 记录触发转人工的具体依据（如“用户要求”、“安抚无效”、“RAG 两次失败”），便于运营审计。 |
| **`handoff_summary`** | `str \| None` | **【转人工交接摘要】** 包含对话历史、意图情绪、命中知识库及建议动作的结构化文本，辅助人工坐席 3 秒快速接手。 |

## 4. 多轮对话 Memory 与指代继承机制

系统通过绑定 LangGraph 的 `InMemorySaver` Checkpointer（基于 `thread_id` 区分不同用户/会话），实现跨轮状态记忆与指代消解：

### 4.1 指代继承效果实测 (基于 `scripts/demo_orchestration.py`)

#### 👉 第一轮对话
* **用户输入**: `“GS3 传感器怎么连不上手机蓝牙？”`
* **编排层内部动作**:
  1. 入口感知节点判定意图为 `使用问题`，提取实体 `product="GS3"`。
  2. `_decide_route` 将 `current_topic` 锁定并存入 Checkpoint 为 `"GS3"`。
  3. 路由至 `product_consultant` 节点，调取《GS3 蓝牙故障指南》并回答。

#### 👉 第二轮对话 (同一 `thread_id`)
* **用户输入**: `“它支持防水吗？”`
* **编排层内部动作**:
  1. 从 Checkpoint 提取上一轮记忆，知晓当前会话主题 `current_topic = "GS3"`。
  2. 感知层结合动态上下文，自动推断代词 **“它” = GS3**，提取主意图为 `产品咨询`。
  3. 路由至 `product_consultant` 节点，调取 GS3 的防水规格参数（IPX8 防水，支持洗澡游泳）精准解答。

#### 👉 第三轮对话 (情绪升级与安抚无效)
* **用户输入**: `“你们服务太差了，搞了半天还是不行，马上给我退款转人工！”`
* **编排层内部动作**:
  1. 感知节点判定情绪为 `愤怒`，诉求包含 `退款转人工`。
  2. 条件路由至 `empathy_agent` 生成共情安抚。
  3. 安抚节点判定符合转人工标准，触发 `Command(goto="after_sales")` 提权至售后节点。
  4. 生成带历史上下文与命中知识库的**转人工交接摘要**，转接人工坐席。
