# 智能客服 AI 感知层业务能力说明书

> **文档性质**: 业务与产品设计规范  
> **适用对象**: 产品经理 (PM)、客服主管、业务运营、交付团队、架构师  
> **核心目标**: 帮助业务团队快速理解智能客服对用户消息的**意图判定、情绪感知与关键信息提取**能力，指导业务场景落地与运营配置。

---

## 1. 核心能力概述

感知层是 AI 智能客服系统的“大脑前瞻耳朵与眼睛”，负责在收到用户第一时间内读懂表达背后的真实诉求。

感知层采用 **零波动确定性输出引擎 (Temperature=0)**，保证对于相同的用户表达，AI 的感知判定结果高度一致、稳定可靠。

```
                    ┌────────────────────────┐
                    │     用户输入自然语言    │
                    └───────────┬────────────┘
                                │
                                ▼
         ┌────────────────────────────────────────────────┐
         │              智能感知引擎 (Perception)           │
         │   (意图分类 + 情绪识别 + 置信度 + 实体提取)      │
         └──────────────────────┬─────────────────────────┘
                                │
          ┌─────────────────────┼─────────────────────┐
          ▼                     ▼                     ▼
 🎯 意图归类 (4类)      😡 情绪感知 (3级)     📊 识别置信度 (0~1)
 (产品咨询/使用问题/     (平静 / 不满 / 愤怒)   (为下游分流与路由
  售后诉求/闲聊)                               提供决策依据)
```

---

## 2. 感知维度与业务标准

### 2.1 4 大业务意图 (Intent)

AI 自动将用户的对话归类为以下 4 种主意图之一：

| 意图名称 | 业务定义 | 典型用户例句 | 后续业务处理动作 |
| :--- | :--- | :--- | :--- |
| **📘 产品咨询** | 询问设备功能、规格参数、兼容性、防水性能、使用原理等知识性问题。 | *“GS3 支持戴着洗澡吗？”*<br/>*“你们传感器保质期多久？”* | 触发 RAG 知识库检索，输出标准产品介绍与使用规范。 |
| **🛠️ 使用问题** | 用户在佩戴或使用设备时遇到故障、连接失败、读数异常、脱落等排障诉求。 | *“蓝牙怎么一直连不上？”*<br/>*“扫码提示设备已绑定怎么办？”* | 引导进入智能故障排障流程，必要时补充追问缺少的信息。 |
| **🎧 售后诉求** | 涉及订单进度、物流查询、退款、退货、换货、补发、保修或明确要求人工服务。 | *“我的订单为什么还没发货？”*<br/>*“传感器坏了，我要退货转人工！”* | 优先开启绿色通道，自动准备工单信息并转接人工客服坐席。 |
| **💬 闲聊问候** | 问候打招呼、感谢、无意义测试或与 CGM 业务无关的内容。 | *“你好呀”*<br/>*“今天天气怎么样”* | 给出礼貌问候与引导，不触发知识库检索。 |

---

### 2.2 3 级情绪识别 (Emotion)

情绪识别与意图判断**完全独立（正交）**。即使客户情绪非常愤怒，AI 仍能精准识别出其核心诉求是“排障”还是“退款”。

| 情绪标签 | 业务信号特征 | 业务处理策略 |
| :--- | :--- | :--- |
| **愤怒 (Angry)** | 强烈怒火、骂人、威胁投诉、强烈宣泄（如：*“垃圾”、“气死我了”、“马上给我解决”*）。 | 优先插入安抚语（共情），简化追问流程，必要时直接提权转接高级坐席。 |
| **不满 (Frustrated)**| 焦虑、抱怨、烦躁（如：*“怎么又不行了”、“到底能不能解决”*）。 | 在回答前附带轻度同理心安抚，给出高优先级排障建议。 |
| **平静 (Calm)** | 客观咨询、正常描述故障、礼貌沟通。 | 直接提供精准、简洁的解答或排障引导。 |

---

### 2.3 识别置信度 (Confidence)

* **置信度范围**: `0.00 ~ 1.00`
* **业务含义**: 代表 AI 判定当前意图的把握程度。
  * **高置信度 (≥ 0.85)**: 用户表达清晰无歧义，系统直接自动执行后续回答或路由。
  * **中/低置信度 (< 0.85)**: 用户表达较为含糊，系统结合上下文或提示策略进行确定性业务澄清。

---

### 2.4 关键实体与转人工标识 (Entities & Handoff)

为了让下游业务节点直接可用，感知层在理解意图的同时，同步提取以下业务实体：

1. **目标产品 (`product`)**: 自动识别用户提及的标准产品型号（如 `GS3`、`GS1`、`ECO`、`硅基手表`）。
2. **故障现象/属性 (`issue`)**: 自动提取用户描述的具体问题（如 *“连不上蓝牙”、“数据偏低”、“传感器脱落”*）。
3. **请求动作 (`requested_action`)**: 提取用户希望进行的动作（如 *“查询”、“排障”、“办理售后”*）。
4. **直通人工标识 (`handoff_requested`)**: 当用户显式说出 *“转人工”、“找坐席”、“要退款”、“索赔”* 时，自动置为 `True`。

## 4. 业务收益与高可用保障

1. **准确率与一致性**: 采用 `Temperature=0` 的模型配置，避免 AI 随机发挥，同一句表达每次感知结果完全一致。
2. **多维正交解耦**: 意图与情绪解耦，解决“用户一骂人系统就懵掉”的行业痛点。
3. **极致业务高可用**: 具备算法兜底机制。即使大模型服务发生网络波动或超时，系统会自动无缝降级为**确定性业务规则引擎**进行感知，确保在线客服系统 100% 稳定运行。
