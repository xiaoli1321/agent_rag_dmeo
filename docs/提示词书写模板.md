# 提示词书写模板

## 目标

为客服 Agent 的不同 LLM 节点提供统一的提示词写法，使提示词职责清晰、输出稳定、便于迭代，并避免用提示词替代确定性业务规则。

## 通用结构

每个提示词按以下顺序书写；不需要的章节可删除。

```md
# 角色与任务
你是【角色】。唯一任务是【可验证的任务目标】。
不负责【不属于该节点的职责】。

# 输入与上下文
- 用户问题：{question}
- 会话主题：{topic_hint}
- 可用资料：{context}

# 执行规则
1. 必须做什么。
2. 可以做什么。
3. 禁止做什么。

# 输出要求
- 输出格式：JSON / Markdown 正文。
- 必填字段或结构。
- 长度、语言、禁止输出的内容。

# 示例（可选）
输入：...
输出：...
```

## 项目内各类 Prompt 的写法

| 类型 | 角色与任务 | 关键规则 | 输出 |
| --- | --- | --- | --- |
| 感知识别 | 只理解用户表达 | 不决定路由、追问或转人工；不编造实体 | 严格符合 `IntentDraft` 的结构化结果 |
| 查询改写 | 把问题改为检索查询 | 保留产品、条件、数量和不确定性；不回答问题 | 单句独立查询及改写理由 |
| 文档评分 | 判断文档能否支撑问题 | 只看问题与文档；不使用外部知识 | `yes/no` 和简短原因 |
| 回答生成 | 基于证据回复用户 | 只使用知识库资料；缺失信息明确说明 | 用户可见的 Markdown 正文，不自造引用 |
| Grounding 检查 | 校验回答是否有证据支撑 | 逐项检查事实、数字和步骤 | `grounded`、不支持的陈述和原因 |
| 共情/闲聊 | 生成场景化客服话术 | 不承诺补偿或时效；不编造产品事实 | 简短自然的用户可见回复 |

## 推荐规则模板

使用“必须 / 允许 / 禁止”表达约束，避免模糊描述：

```md
## 执行规则
1. **必须**：仅依据【输入资料】完成回答。
2. **允许**：改写、归纳和重组资料中的信息。
3. **禁止**：补充资料中不存在的参数、步骤、价格、时效或医疗建议。
4. **资料不足时**：说明当前无法确认的部分，不得猜测。
```

## 维护原则

1. 一条提示词只服务一个节点职责；路由、阈值和转人工规则留在 Python 策略层。
2. 规则按优先级排列，硬约束放在角色说明后和输出要求前后各强调一次即可。
3. 示例只覆盖易错边界，例如“有产品名但问题无关”“有情绪但仍是使用问题”。
4. 修改后至少验证：输出格式、拒答边界、是否出现新增事实，以及 LangSmith 中的输入长度与延迟。
